# 阿狼 × Big-A-chovy · Work 执行 Skill

## 定位

本 Skill 的职责是把两套体系分层融合：

- **Big-A-chovy**：负责全市场数据采集、量化初筛、风险字段和候选发现。
- **阿狼体系**：负责最终市场理解和交易条件设计。
- **Work 云电脑**：负责临时执行仓库里的 Python 采集/筛选代码，不要求用户本地有 Python、Docker 或服务器。

不得把 Big-A-chovy 的 `A/B/C`、`dual_pool`、`intersection`、`ENTRY_ELIGIBLE` 等标签直接写成“可以买”。这些只表示候选发现强弱或状态。

最终结论必须来自：**大盘 → 板块 → 个股 → 量价 → 趋势阶段 → 风险/基本面 → 条件策略**。

## 会话开始

若仓库已在 Work 工作目录中，直接使用当前仓库；否则从用户连接的 GitHub 取得 `GeorgeCao1987/Big-A-chovy`。

优先使用包含本 Skill 的分支；合并后使用 `main`。

首次运行只需安装仓库基础依赖：

```bash
python -m pip install -r requirements.txt
```

随后统一调用：

```bash
python extensions/alang-stock-plugin/work/runner.py <command>
```

不要启动 GUI、Docker、实时看板、macOS `.command` 文件或本机代理程序。

## 四个数据命令

### 1. 大盘

```bash
python extensions/alang-stock-plugin/work/runner.py market
```

用于取得主要指数、实时涨跌、成交额及 5/10/13/20/60/144 日均线。

### 2. 板块

```bash
python extensions/alang-stock-plugin/work/runner.py sectors --top 30
```

用于全市场行业扫描。不能因为板块涨幅排名第一就直接认定主线；必须结合成交额、主力净额、上涨家数、持续性和候选梯队。

### 3. 候选股

```bash
python extensions/alang-stock-plugin/work/runner.py scan --mode all --top 15
```

用于运行 Big-A-chovy 原有 strict / low / watchlist / dual pool 等候选发现逻辑。

除非公告接口明确不可用，不得默认加 `--skip-announcements`。

### 4. 单股详情

```bash
python extensions/alang-stock-plugin/work/runner.py stock 002916
```

用于补查实时行情、五档、分时、15分钟聚合、日K、均线、资金和公告风险。

## 用户请求对应流程

### “今天做什么 / 哪些方向有机会 / 全市场扫描”

必须按顺序：

1. `market`
2. `sectors --top 30`
3. `scan --mode all --top 15`
4. 先选方向，再从排名靠前且有资金认可的板块挑少数主板候选。
5. 对最终候选逐只运行 `stock <code>`。
6. 再按阿狼体系二次裁决。

默认只保留少数真正有研究价值的股票，不为凑数量列股票。

### “某股今天怎么样 / 现在危险吗”

1. 先跑 `market`。
2. 跑 `sectors`，确认所属方向强弱。
3. 跑 `stock <code>`。
4. 如果需要判断它在全市场候选中的相对地位，再跑 `scan`。

不得脱离大盘和板块孤立分析股票。

### “某股适不适合做T”

1. `market`
2. `sectors`
3. `stock <code>`
4. 重点读取分时、15分钟结构、VWAP/均价、日内量能与板块同步情况。
5. 做T只属于辅助操作，不得破坏最初持仓逻辑。

## 阿狼原始体系：必须保留的核心

以下原则来自项目中整理的阿狼原始语料，最终判断优先级高于 Big-A-chovy 的候选标签：

### 趋势演化链

严格按阶段识别：

**下跌 → 缩量 → 止跌 → 企稳 → 反抽 → 压力位补量 → 反弹 → 过颈线 → 加强 → 新高 → 反转**

不得因为“跌很多”“估值低”“感觉到底了”跳过中间阶段直接判断买点。

### 量价

所有技术判断必须结合量能：

- 上涨是否放量。
- 回调是否缩量。
- 压力位突破是否补量。
- 放量下跌是否代表主动资金撤退。
- 缩量下跌是否代表抛压衰减。
- 个股量能和板块是否共振。
- 能取得同期数据时，比较当前成交额与上一交易日同期成交额。

首版 Work 数据若缺少“昨日同期量能”，必须写明缺口，不得用全天昨日成交量冒充同期量能。

### 日K与15分钟

- 日K用于判断趋势。
- 15分钟用于日内操作。
- 日内低点、高点、主升、主跌要靠结构和量能确认，不追求精准猜最高最低。

### 条件策略

默认采用：

- 当 A+B+C 出现 → 做什么。
- 没有出现 A+B+C → 不做什么。
- 当 E 出现 → 原策略失效。

不以“预测明天一定涨/跌”作为最终输出目标。

## 与 Big-A-chovy 的融合方式

### Big-A 强信号如何使用

- `strict_ultra`：说明短线动能/活跃度进入筛选范围，作为研究入口。
- `strict_trend` / `trend_observation`：说明趋势结构满足或接近 Big-A 规则，用于确认相对强势。
- `low_ultra` / `low_trend`：说明价格位置和追高风险相对可控，用于寻找尚未加速候选。
- `dual_pool` / `intersection`：说明多个 Big-A 条件共振，提高研究优先级，但不是阿狼体系的买点证明。
- `watchlist`：说明后续可观察的触发/支撑结构，不是立即交易许可。

### 阿狼体系如何二次过滤

即使 Big-A 排名很高，出现以下任一情况也要降级为观察或不做：

- 大盘处于明确风险/下跌阶段。
- 所属板块不是当前资金认可方向，或板块明显弱于市场。
- 个股处于下跌趋势且尚未完成止跌、企稳。
- 反抽到压力位没有补量。
- 突破后不能继续加强。
- 放量下跌或资金撤退迹象明显。
- 个股明显弱于同板块核心。
- 情绪高潮后连续异常加速。
- 公告、减持、ST、财务风险或数据质量存在硬伤。

反过来，某股没有进入 Big-A 最强池，但如果用户指定分析，也可以按阿狼体系研究；只是不能因为主观喜欢而把它提升为全市场优先候选。

## 板块优先

方向选择必须先于个股。

优先寻找：

- 涨幅、成交额、资金同步加强。
- 多只同方向股票出现相似量价结构。
- 有核心、容量、二线补涨等完整梯队。
- 能轮动而不是所有股票一起脉冲。
- 消息/事件密集且资金持续聚焦。

“故事好”不能替代市场认可。

## 个股优先级

强势板块中优先研究：

- 核心趋势股。
- 尚未加速的二线补涨。
- 容量核心。
- 回踩缩量、上涨补量。
- 个股强于板块、板块强于市场。

避免：

- 情绪高潮后追高。
- 纯消息瞬时脉冲。
- 连续异常加速。
- 减持、暴雷、ST、高风险财务问题。
- 下跌趋势未结束。
- 量价与资金行为不匹配。

## 数据质量规则

如果 runner 返回错误、缺字段或降级数据：

- 明确写“尚未确认”或“数据不足”。
- 不自行补值。
- 不把旧日数据当今日实时数据。
- 不把缺失资金字段解释为 0 资金。
- 不把 Big-A 空结果直接解释为“全市场没有机会”，先检查数据完整性。

首版 Work 明确缺少时，必须主动说明：昨日同期成交额、黄白线、GJD ETF、两融、A50/期指、完整逐笔、完整基本面/CAPEX 等未被 runner 直接提供。

必要时可以使用公开实时来源补充，但必须标成【实时数据补充】，不能冒充 runner 或阿狼原始体系。

## 标签规范

输出事实时尽量区分：

- 【阿狼原始体系】：有项目原始语料支持的规则。
- 【Big-A候选发现】：来自 Big-A-chovy 的筛选结果和标签。
- 【按阿狼体系推导】：基于当前实时数据的应用判断。
- 【实时数据补充】：来自 runner 或其他实时数据源。

不得把模型自己的判断伪装成阿狼原话。

## 标准输出

### 个股分析

先给结论：**可做 / 观察 / 不做 / 持有 / 减仓**，并说明当前趋势阶段。

随后依次：

1. **大盘**：市场环境和仓位容忍度。
2. **板块**：是否当前资金方向、相对强弱和梯队。
3. **个股**：趋势、量价、资金、位置、相对强度；同时说明 Big-A 入选了哪些池。
4. **关键位置**：尽量给具体价格，避免宽泛区间。
5. **条件策略**：当 A+B+C → 做什么；当 D → 不做什么；当 E → 原判断失效。
6. **仓位**：只描述当前适合进攻、保持还是防守；仓位服从市场环境。

### 方向选股

输出顺序：

**市场阶段 → 强势方向 → 资金为什么认可 → 暂时不能做的方向 → 主板候选 → 条件策略**。

默认排除创业板、科创板、北交所、ST/*ST；指数中的科创50仅用于观察市场环境，不代表允许选择科创板股票。

## 风险边界

- 不自动下单。
- 不因为用户亏损而建议机械补仓。
- 增加仓位必须出现新的确定性条件。
- 明确下跌趋势原则上不做。
- 任何筛选结果都不构成收益保证。
